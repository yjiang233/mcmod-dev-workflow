# 触发验收查询集

用于验证触发边界。正例应命中本技能，负例**一条都不许命中**（负例命中即一票否决）。

用户选择了「中触发·所有 NeoForge/Forge」，因此正例覆盖 Python/Java 双版本与其它工程；为守住不抢活儿，触发条件附加了**动作限定**：必须是改码／构建／验证／排查／发布／同步文档之一。

## 5 条正例

| # | 查询 | 期望 | 理由 |
| --- | --- | --- | --- |
| 1 | 「给这个 NeoForge 模组加个新方块，走一遍构建验证」 | 命中 | 改码 + 构建 + 验证，完整工作流 |
| 2 | 「客户端一进世界就崩，帮我查一下日志」 | 命中 | 排查崩溃属于过程编排 |
| 3 | 「改完记得同步 Obsidian，顺便看看有没有漏掉踩坑」 | 命中 | 知识库同步是本技能红线之一 |
| 4 | 「现在可以提交了，两个分支都要发 Release」 | 命中 | 用户明确解除红线，进入发布编排 |
| 5 | 「把这次渲染黑屏的根因整理进开发日志」 | 命中 | 沉淀踩坑经验 |

## 5 条负例

| # | 查询 | 期望 | 理由 |
| --- | --- | --- | --- |
| 1 | 「用 Blockbench 给这个方块做个模型」 | 不命中 | 归 `blockbench-modeling`，本地已有 15 个同类技能 |
| 2 | 「生成一张 16×16 的循环动画贴图」 | 不命中 | 归 `blockbench-flipbook-textures`，纯美术 |
| 3 | 「剪一条介绍这个模组的视频」 | 不命中 | ChatCut 系列，完全无关 |
| 4 | 「写个原版数据包，加个战利品表」 | 不命中 | 纯数据包，非 Java 层开发 |
| 5 | 「DeferredRegister 怎么用？给我讲讲原理」 | 不命中 | 纯 API 用法咨询，交给官方文档/通用 API 技能 |

## 装 / 不装基线对比（静态推演）

以下是按查询语义做的**静态推演**，不是真实装载后的路由日志；本环境没有技能路由运行时，无法跑实测对比。

| 场景 | 不装本技能 | 装本技能 |
| --- | --- | --- |
| 正例 1 | 直接改码，常忘记停客户端就 build、忘记写 Obsidian、可能顺手 commit | 按 7 步走，构建前清进程，收尾同步知识库并停手 |
| 正例 2 | 从代码盲猜，容易把「旧进程占端口」当成代码问题 | 先查端口 PID 与日志，按环境/渲染 reference 顺序排除 |
| 正例 4 | 可能只提交一个分支，或 tag 串版本 | 双分支清单逐项核对后再执行 |
| 负例 1–5 | 由对应专业技能处理 | 因动作限定与硬负例，**不应**被本技能截走 |

## 已知残留风险

- 负例 5 的边界最薄：「DeferredRegister 怎么用，顺便帮我改一下工程」这类混合查询可能同时命中。处理原则是**让路给 API 解答，只在出现实际改码动作时接管过程**。
- 中触发天然比窄触发更容易与通用 `minecraft-modding` 技能同时命中。若后续观察到两者互相干扰，把触发范围收回「窄触发·本项目」即可，改动只在 `SKILL.md` 的「何时使用」段落。
