# 贴图、模型与资源复用

面向「照着别的模组的资源复刻外观」这类需求，记录可复用的流程与容易翻车的地方。

## 复用流程

1. 从目标模组/整合包导出原始资源（PNG + `.png.mcmeta` + 模型 JSON），保留目录结构作为只读素材。
2. 复制贴图进本模组 `assets/<modid>/textures/block/`，**同时复制 `.mcmeta`**，否则动画会丢或整条动画贴片被当成一张图。
3. 模型用「外壳六面 `cullface` + 正面单独一个 0.001～0.01 偏移的单面 overlay 贴片」组合，避免 z-fighting。
4. 带朝向的方块在 blockstate 里按 `facing` 写四个 `y` 旋转变体，方块类补 `FACING` 属性与 `getStateForPlacement` / `rotate` / `mirror`。
5. 物品模型指向对应方块模型；若 blockstate 有多个变体，物品模型要指向一个确定的模型，否则背包里可能丢图标。
6. 贴图与模型数量多时用生成脚本产出 JSON，脚本与源素材一起保留，便于重跑。

## 动画贴片的坑

- 动画贴图是**竖条**（例如 16×96 表示 6 帧）。若 `.mcmeta` 没跟过来，游戏会把整条当一张图，UV `[0,0,16,16]` 只取第一帧。
- 第一帧本身可能就是「整面黑底 + 边框」的图案，铺满整个正面会变成一个黑洞。**先单独把第一帧放大看过，再决定要不要整面铺**。
- 自制正面贴图时留透明边距（约 3px），让外壳纹理露出来；不留边距会把外壳完全盖掉，方块看起来像一块灰板。

## 自动连接纹理（自研 CTM）

不依赖其它模组的做法：

- 把 16×16 底图按「四向连接掩码」拼成 64×64 图集（16 个格子），只在断头边描边。
- 生成 16 个模型：顶/底用图集 UV 子格 `[c*4, r*4, c*4+4, r*4+4]`，四侧用底图；再生成 16 变体 blockstate。
- 方块类用四个 `BooleanProperty`，在 `onPlace` / `neighborChanged` / `updateShape` 里重算连接状态。
- 物品模型指向「全连接」那一格，避免图标显示为空白。

## 其它

- 用 `BLOCKS.register` 注册的方块**不会自动生成 BlockItem**，需显式 `ITEMS.register`，否则创造栏取到 air 栈直接崩。
- 复刻 GUI 风格时优先复用目标模组的原生贴图（面板九宫格、槽位、复选框、按钮、页签），不要手绘替代品。
- 改完网页前端若预览仍旧脚本，给静态资源 URL 附版本号刷新即可。
